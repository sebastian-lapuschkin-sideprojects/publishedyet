How publishedyet works

During revisions, references to preprints go stale: the paper has appeared in a journal or at a conference in the meantime. publishedyet finds such preprints in a BibTeX file or a list of ids, shows their known publications, and returns a fixed BibTeX file.

What it takes off your hands

The chores of cleaning up a bibliography before submission or during a revision:

  • finding out, for every cited preprint, whether it has been published since: at a conference, in a journal, as a workshop paper, or as an extended version;
  • replacing outdated preprint entries by the published version, under the same citation key, so the .tex files stay as they are, and keeping the old entries as comments;
  • choosing between several publications of one preprint (say a workshop paper and its journal extension), with a preferred one suggested;
  • writing the preprints that remain in one uniform style instead of a mix of Google Scholar, arXiv and DBLP entries;
  • giving new entries citation keys in one style (Google Scholar's author2024word or DBLP's);
  • citing papers the way their venue asks (PMLR's entries for ICML, OpenReview's form for ICLR);
  • getting names right where sources mangle them (umlauts and accents, hyphenated first names such as Klaus-Robert, which BibTeX shortens to K.-R.);
  • spotting entries that lack pages, volume or a DOI;
  • showing exactly what changed, as a diff;
  • pointing co-authors to the references in their paper that need updating (share links);
  • and doing each lookup only once: confirmed results go into a shared database that everybody's next run uses.

Everything runs in your browser

The page runs Python in your browser (Pyodide); there is no server behind it. Your BibTeX file is not uploaded anywhere. What leaves your computer are the preprint ids and, for searching, the titles of those preprints: to this site's database, and to DBLP, OpenAlex, Crossref, the bioRxiv API and PMLR, all of which are public services.

1. Reading the input

publishedyet recognises arXiv ids (new ones like 2402.05602, old ones like hep-th/9901001, with or without version), bioRxiv and medRxiv DOIs (10.1101/… or just 2020.07.23.217034) and OpenReview links. In a BibTeX file, an entry counts as a preprint if it mentions such an id (as eprint, DOI, link or "arXiv preprint arXiv:…") and names no other venue. Entries that are published already are left alone. Anything in a list of ids that cannot be read is shown with a warning.

2. The database

Each preprint is first looked up in this site's own database: one file per preprint, with the publications people have confirmed, complete BibTeX data for each, and one marked as preferred. Database entries are checked by a person before they go in.

3. Searching online

Preprints not in the database are searched for right away, in these places:

  • DBLP (computer science): the arXiv version's record leads to its first author; among that author's publications, those with the same title (at least 90 % similar) count as published versions.
  • OpenAlex: often merges a preprint with its published version, which shows up when looking the preprint up by its DOI. Otherwise a title search.
  • Crossref: a title search among journal articles, proceedings papers and book chapters.
  • bioRxiv: its API names the journal article a preprint turned into.

A search hit counts as the same paper if its title is at least 90 % similar to the preprint's and the preprint's first author is among its authors. Details then come from DBLP or from Crossref (via the DOI). Where possible, the venue's own BibTeX is used: PMLR's for ICML and other PMLR conferences, and the form OpenReview uses for ICLR.

Matches found online are marked found online until someone confirms them for the database. Entries missing data that a complete citation would have (pages, volume, …) are marked incomplete.

Not found automatically: non-archival workshop papers, journal extensions with a new title, papers only on OpenReview, and conference papers outside computer science without a DOI. These need a database entry.

4. Choosing and exporting

Each preprint gets a card: choose a publication, keep the preprint, correct any field with edit, or add a publication by hand. The fixed BibTeX file keeps your citation keys, so your .tex files need no change. Replaced entries stay in the file as comments (with their @ removed, since BibTeX has no comment character and would otherwise still read them). Preprints that stay can be rewritten in one uniform style (Google Scholar, arXiv or DBLP).

5. Giving back

propose opens a prefilled GitHub issue with the entry. A GitHub action turns it into a pull request, which a maintainer reviews before the entry goes into the database. share link copies a link that opens this page with the same preprints, for pointing co-authors to references that need updating.

publishedyet: keeps the references of a paper up to date. Data from its own database, DBLP, OpenAlex, Crossref, bioRxiv and PMLR.
